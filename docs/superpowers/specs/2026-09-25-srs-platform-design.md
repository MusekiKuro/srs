# SRS Platform — генератор СРС и отчетов по практике

## Цель

Создать публичную веб-платформу, где студент вводит тему, тип работы и объем,
получает план и текст по главам с помощью ИИ, правит их в браузере и скачивает
готовый `.docx` по стандартному ГОСТу. Каждый пользователь работает со своим
ИИ-ключом — платформа не платит за чужой расход и не требует бэкенда.

## Пользовательский сценарий

1. Пользователь открывает общую ссылку, видит список «Мои работы».
2. Нажимает «Новая работа», вводит тему, тип (СРС / отчет по практике) и нужный объем в страницах.
3. Нажимает «Составить план» — модель предлагает список глав как черновик.
4. Правит план вручную (переименовывает, переставляет, удаляет, добавляет) и жмет «План принят».
5. Нажимает «Написать текст» — генерация идет по главам по очереди, текст появляется
   в каждой главе по мере генерации. Отдельная глава пишется кнопкой прямо в ней.
6. Правит текст вручную прямо в редакторе.
7. Заполняет список литературы вручную или кнопкой «Сгенерировать по главам».
8. Нажимает «Скачать .docx» и получает файл по ГОСТу без титульника.

## Границы первой версии

- Публичный доступ без входа и регистрации.
- Каждый пользователь вводит свой ИИ-ключ в настройках; ключ хранится только в его браузере.
- Данные и документы обрабатываются и хранятся только в браузере (`localStorage`), на сервер не отправляются.
- Наружу уходят только запросы к выбранному ИИ-провайдеру.
- Веб-поиск материала по интернету НЕ входит в первую версию: текст пишется из знаний модели.
- Титульный лист НЕ генерируется: первый лист файла — содержание.
- Основной язык интерфейса и документа: русский.
- Адаптивная верстка для телефона и компьютера.

Не входят в первую версию: веб-поиск, авторизация, серверное хранение, совместное
редактирование, отправка по email, PDF, база шаблонов.

## Архитектура

- Статическое SPA на React + Vite, без бэкенда.
- Запросы к ИИ идут напрямую из браузера к OpenAI-совместимому endpoint (`POST {baseUrl}/chat/completions`, стриминг).
- Генерация DOCX выполняется в браузере библиотекой `docx` (порт скрипта `create_docx.py` из скилла).
- Деплой — Vercel из корня репозитория.
- Серверные функции, база данных и секреты не требуются.

### Модули

| Модуль | Задача |
|---|---|
| `src/lib/llm.js` | Запросы к OpenAI-совместимому API, стриминг ответа |
| `src/lib/outline.js` | Промпты для плана и текста, разбор ответа модели в структуру |
| `src/lib/docx.js` | Сборка `.docx` по ГОСТу |
| `src/lib/storage.js` | Чтение/запись документов и настроек в `localStorage` |
| `src/state/store.js` | Текущий документ + список работ (useReducer + Context) |
| `src/components/*` | Экраны и редактор |

### Модель данных

```js
Document = {
  id, title,                    // тема работы
  kind: 'srs' | 'practice',     // тип работы
  pages,                        // нужный объем
  createdAt, updatedAt,
  chapters: [{ id, heading, level: 1 | 2, paragraphs: [] }],
  bibliography: [ "...готовая строка по ГОСТу..." ]
}

Settings = { baseUrl, apiKey, model }   // отдельно, НЕ внутри документа
```

Настройки лежат отдельно от документов, чтобы ключ не уезжал вместе с работой
при экспорте и не светился в списке документов. `localStorage` (~5 МБ хватает
на сотни работ) с обработкой превышения квоты.

## Интерфейс

- Рабочая область сразу без маркетингового лендинга: первый экран — список работ.
- **Экран «Мои работы»:** карточки (тема, тип, объем, дата, кол-во глав), кнопки «Новая работа» и удаления, пустое состояние с кнопкой-призывом.
- **Форма новой работы:** тема, тип, объем в страницах.
- **Редактор:** две колонки — слева оглавление глав (клик открывает главу, кнопки «+ глава»),
  справа содержимое главы (поле заголовка + редактор абзацев, каждый абзац — свое поле).
- Действия в редакторе: «Составить план», «План принят», «Написать текст», «Сгенерировать по главам»
  (литература), «Скачать .docx», «Настройки».
- **Настройки (модалка):** baseUrl, ключ, модель + пресеты (OpenAI, OpenRouter, DeepSeek, Groq, «свой URL»
  для локальных Ollama/LM Studio) + честное предупреждение, что ключ доступен всем, у кого открыт этот браузер.
- Состояния: пустая работа, черновик плана, генерация (видно как текст пишется), ошибка API, скачивание.
- Визуальная система: спокойная деловая палитра, читаемая типографика, заметные кнопки действий.

## Правила валидации

- Нет ключа ИИ → кнопки ИИ неактивны: «Укажите ключ в настройках».
- Текст пишется только после принятого плана.
- «Написать текст» активна, когда есть план (главы с пустым текстом — нормально).
- «Скачать» неактивна, пока нет ни одной главы с текстом.
- «Сгенерировать по главам» (литература) активна, когда есть хотя бы одна глава с текстом.
- Ошибки показываются рядом с действием; написанный текст при ошибке не теряется.

## Промпты ИИ

- **План:** модель обязана вернуть строго JSON вида `[{heading, level}]`. Разбор строгий:
  если модель завернула JSON в лишний текст — выдираем, если не вышло — показываем ее ответ и кнопку «повторить».
- **Текст главы:** просим N абзацев без заголовка и без markdown-разметки (заголовок у главы
  уже есть, иначе он продублируется в содержании).
- **Литература:** модель собирает источники из того, на что ссылался текст, готовыми строками по ГОСТу.
- **Объем:** считаем, сколько страниц уже написано (~300–350 слов на страницу), и генерируем
  ровно столько, сколько не хватает.

## Формат документа

- Бумага А4, поля: левое 30 мм, правое 10 мм, сверху/снизу 20 мм.
- Основной текст: Times New Roman 14, межстрочный 1.5, по ширине, отступ первой строки 1.25 см, интервалы до/после 0.
- Заголовки стилями Heading 1 (главы, по центру, с новой страницы) и Heading 2 (параграфы, слева), без точки в конце.
- Содержание — автооглавлением через поле TOC, обновляется в Word по правому клику.
- Нумерация страниц: снизу по центру, Times 12.
- Первый лист файла — СОДЕРЖАНИЕ, титульника нет.
- Список литературы в конце по ГОСТ Р 7.0.5-2008 (упрощенно).
- Никаких служебных подсказок внутри файла (например «обновите поле») — они только в интерфейсе.

## Ошибки и ограничения

- Неверный ключ (401) → «Проверьте ключ в настройках».
- Лимит токенов → «Разбейте работу на части» (писать по одной главе).
- Обрыв сети → глава остается как есть, кнопка «повторить».
- Превышение квоты `localStorage` → понятное сообщение с предложением удалить старые работы.
- Если браузер не поддерживает скачивание файла → понятное сообщение.
- Приложение не отправляет введенные данные никуда, кроме выбранного ИИ-провайдера.
